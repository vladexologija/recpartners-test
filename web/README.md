# web

The React + TypeScript frontend (Vite). It uploads an MP4 straight to storage, follows the job over server-sent events, and plays the video with the hot-dog boxes drawn on top.

## Commands

```bash
pnpm install
pnpm dev:mock    # UI against an in-memory mock of the API and storage (mock/mockApi.ts)
pnpm dev         # UI against the FastAPI server on localhost:8000 (proxied under /api)
pnpm test        # the requirement tests (see docs/requirements.md)
pnpm test:coverage
pnpm typecheck
pnpm build       # outputs dist/, which the API serves in production
```

With `dev:mock`, a job takes about 20 seconds. A filename containing `nohotdog` finishes without detections, and one containing `fail` fails.

## Routes

| Path | Page |
|---|---|
| `/` | Upload a video |
| `/videos/:id` | A video's status, player and result. The app opens it once the upload has landed, and reloading it mid-job comes back to the same video. |

These are client-side routes (React Router), so the server must answer every non-`/api` path with `index.html`. The Vite dev server and `vite preview` already do; the FastAPI server does it in production.

## API contract

`src/api/types.ts` is the contract the backend implements:

| Endpoint | Purpose |
|---|---|
| `POST /api/videos` `{id, filename, size}` | Creates the video (the id is generated by the browser) and returns a signed upload |
| `PUT <signed URL>` | The browser uploads the file straight to GCS, sending exactly the returned headers |
| `GET /api/videos/{id}` | The video, with its analysis as a child object; 404 if there is no such video |
| `GET /api/videos/{id}/events` | SSE, opened only while the analysis runs: the video (`event: video`) on connect and on every change |
| `GET /api/videos/{id}/playback` | A signed GET URL for the uploaded file |
| `GET /api/videos/{id}/detections` | Boxes (normalized 0–1) with timestamps, the sample rate and the display threshold |
| `POST /api/videos/{id}/reprocess` | Deletes the results and starts the analysis over; returns the video, its analysis queued again (409 while it is processing) |

## Where things are

```
src/
  main.tsx        entry: the router and the root render
  App.tsx         the route table
  routes.ts       URL builders
  config.ts       upload limits
  api/            the API client and its typed contract (types.ts)
  pages/          one thin component per route: reads the URL, handles navigation, renders a feature
  features/       self-contained parts of the UI; features never import each other
    upload/       Uploader: browser pre-checks (size, MP4 signature, playable, duration) and the signed upload
    video/        VideoDetails and its hooks: the video, loaded with a GET and followed over SSE while its
                  analysis runs (useVideo), the signed playback URL (usePlaybackUrl) and the results
                  (useDetections); the status panel, the verdict, the player with an SVG overlay
                  that letterboxes like object-fit: contain, and Reprocess
  lib/            small helpers shared across the app
  test/           test doubles shared by the tests
```

Tests sit next to the code they cover (`*.test.ts[x]`). Tests that need a browser environment say so in a first-line comment (`// @vitest-environment jsdom`); `validate.dom.test.ts` is the browser half of the `validate.ts` tests.
